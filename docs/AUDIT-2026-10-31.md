# CineSort Deep Audit — 2026-10-31

Scope: full codebase (79 Kotlin files, 5 modules), build files, resources,
manifest, and the spec (`CineSort_Master_Prompt.md`). Method: mechanical
cross-reference checks, hard-rule greps, line-by-line review of high-risk
files, fuzz testing, and behavioral tests of the metadata service against a
local mock server. Labels: **CONFIRMED** = backed by source/compiler/test
evidence; **UNVERIFIED** = cannot be settled in this sandbox (needs the
Android Gradle build / a device).

## Confirmed defects — fixed in this pass

1. **Remembered corrections never rescued unrecognized files.**
   `OrganizePlanner.stagedItem` returned Needs-review for `Unrecognized`
   parses without consulting title overrides, although the code comment (and
   spec §6.6) say an override can rescue them. The session already persisted
   such overrides keyed by the normalized file-name base, so the data was
   written but never read.
   Fix: the planner now synthesizes a MEDIUM-confidence movie from a
   movie-type override for unrecognized files. Episode-type overrides cannot
   be synthesized (they carry no season/episode numbers) and stay in
   Needs review. Two regression tests added.

2. **Tink AEAD called with `null` associated data** (`SecretStore`).
   Encrypt/decrypt now both pin an explicit empty AAD byte array, avoiding
   provider-dependent null handling in Tink's AES-GCM primitive.

## New verification added

- **MetadataService behavioral suite (10 tests, all passing)** against
  MockWebServer: TMDB search+details success, positive cache (second lookup
  makes no HTTP call), negative cache, the §9.3 year-less retry, OMDb
  search-fallback chain (§9.2), OMDb quota error degrading to "unavailable"
  *without* being cached as not-found, HTTP 401 uncached, malformed JSON
  degrading to null, 429 honoured once via `Retry-After`, no-keys ⇒ no HTTP,
  and v3 key placement in the search request. These tests run in CI via
  `:core:data:testDebugUnitTest` (mockwebserver test dependency added).
  Note: the service performs **two** TMDB calls per uncached lookup
  (search, then details) and up to **three** OMDb calls (byTitle → search →
  byId) — the first version of the test fixtures under-enqueued responses
  and starved on the mock server; fixtures were corrected, the service was
  right.
- **Parser fuzz (20,000 random release-style names):** never throws,
  deterministic across runs, sane title/season/episode ranges.
- **Folder-naming fuzz (5,000 parser outputs):** produced folder names are
  non-blank, separator-free, have no trailing dot/space, and stay within the
  240-byte cap with the year surviving truncation.

Local suite after this pass: **67/67 tests passing**
(57 pure parser/domain/metadata-logic + 10 metadata-service).

## Mechanical checks — all passing

- Version-catalog aliases: every `libs.*` reference in every module build
  file exists in `gradle/libs.versions.toml`; plugin aliases likewise.
  The only direct dependency coordinate is the documented desugar library.
- Cross-module imports: every `com.cinesort.*` import resolves to a declared
  symbol (remaining hits are generated `R`/`BuildConfig` and extension
  functions, verified by hand).
- Resources: all 271 `R.string.*` references exist in both `values/` and
  `values-fa/` (exact key parity, 287 keys each).
- Hard rules (grep-verified): no broad storage permissions anywhere;
  manifest declares exactly INTERNET, POST_NOTIFICATIONS, FOREGROUND_SERVICE,
  FOREGROUND_SERVICE_DATA_SYNC; `DocumentsContract.renameDocument` is used
  exactly once — renaming the `.cinesort-part` temp file to the original
  file name inside the verified copy (§5.5), never to rename user media;
  the only remote hosts in code are api.themoviedb.org, www.omdbapi.com,
  image.tmdb.org; cleartext traffic is disabled.
- SAF gateway read-through: breadth-first cursor enumeration, per-volume
  move fast path gated on `FLAG_SUPPORTS_MOVE`, verified-copy path with
  free-space pre-check, byte-count verification, partial cleanup on any
  failure including cancellation; `applicationContext` only (no leaks).
- Worker/session wiring: input key `runId` matches on both sides; drafts
  carry everything the worker needs to rebuild a run after process death.

## Observations (accepted, not defects)

- 16 string resources are defined but not yet referenced (kept for planned
  surfaces).
- `ExistingFolderMatcher` strips a trailing genres group only when it starts
  with a Latin letter; the app only ever writes canonical English genre
  names (§9.5), so app-written folders always match. Foreign folders with
  non-Latin genre groups fall back to a fresh folder.
- If the post-copy source delete throws, the executor conservatively marks
  the item failed (the copy exists in the destination; the source is kept).
- The HOLD behaviour treats a fully-empty enrichment batch as "metadata
  unavailable" (offline / bad key / quota are indistinguishable from
  all-not-found at batch level).
- Retry-from-plan reuses the previous plan; items that newly conflict fail
  visibly in the report instead of being silently re-planned.
